See what a specific payment does to one customer's own account, not just the portfolio total.
Uses this customer's current position aggregated across all countries. When aging roll-forward is on, it uses the same history-calibrated rates as the portfolio simulator above. Manual allocation pays down disjoint aging bands directly (a euro applied to ">90" also reduces the 60+ and overdue totals it's part of, since those buckets are cumulative, not separate pools). "Applied to AR not yet overdue" reduces Total AR without touching Overdue/GT60/GT90. "Left as Unapplied Cash" increases UAC instead of paying down any invoice — Total AR is unaffected. In Manual mode the Payment type dropdown above is ignored; each band's destination is set explicitly by these fields instead.

Report Logic
MTD snapshot filtering: When RawData contains multiple daily extracts within the same calendar month, only the rows from the latest snapshot date are used. This prevents accumulation of daily balances and ensures KPIs reflect a true point-in-time position.

Included fields: Total AR € (Live), Overdue € (Live), > 60 days € (Live), > 90 days € (Live), Gross Sales € (Live), Total UAC € (Live), Total Payments € (Live).
Excluded fields: DSO, TDSO, TDSO Gap, Payment Term, and all non-live EUR columns from KPI calculations.
Customer views: Customer tables show top risk customers, customer MoM, and same-month YoY views.
Country summary: Countries are ranked by latest-month Total AR and include overdue, aging, gross sales, and status indicators.
UAC section: UAC views show Total UAC, UAC % of AR, payments, top UAC customers, country UAC exposure, and UAC exceptions.
Simulator: Directional estimate only. It uses aggregated aging values and user assumptions because invoice-level due dates are not available in the raw data.
Trend charts: Each month point in the trend reflects the latest snapshot for that month, not a cumulative sum.
